Ready-Made Components for CMU's Web Template

The Carnegie Mellon Web Kit fills the gaps in Carnegie Mellon's web template, for Cascade sites and for web apps that use the same template.

Two Files, Two Layers

FileLoad it onWhat's in it
cmu-cms.cssCMS sites and appsColors and page content: hero, path cards, steps, check lists, callouts and notes, text with a screenshot, pills, tables, "On this page" box
cmu-app.cssApps, after cmu-cms.cssForms, tabs, flash messages, dialogs and file drop zones, the bulk selection bar, row buttons, sortable headers, filters, progress bars, folded lists, panels

Your site or app adds its own stylesheet last, for whatever is particular to it, with its own prefix.

Add It to a Page

Load the template first, then the kit, then your own stylesheet. Use <link> tags rather than CSS @import, which makes the browser load the files one after another.

<link href="https://www.cmu.edu/common/standard-v6/css/main.6.7.min.css" rel="stylesheet">
<link href="https://cdn.jsdelivr.net/gh/CMUTLI/cmu-web-kit@0.1.0/css/cmu-cms.css" rel="stylesheet">
<link href="https://cdn.jsdelivr.net/gh/CMUTLI/cmu-web-kit@0.1.0/css/cmu-app.css" rel="stylesheet">  <!-- apps only -->
<link href="/your-site.css" rel="stylesheet">

Add It to a Cascade Site or an App

Rules

  • The template comes first. See what it already has on CMU Standard, and use its classes as they are: btn, btn small, ghost, cta, table.alternate, .sidebar, .sr-only. The kit never copies the template's rules or values, and adds a class only where the template has nothing.
  • Everything in the kit starts with cmu-: classes, custom properties (--cmu-red) and, later, JavaScript hooks. Variations use a double hyphen (cmu-pill--green). Give your own classes your own prefix, never cmu-.
  • Versions follow semver. Renaming or removing a class is a new major version.

Template Quirks to Know

  • Tables are display: block so they scroll on phones, which stops them stretching. Add cmu-full to stretch one to full width from 768px up.
  • The template's script removes style="" from spans. Use a div when you need an inline style, such as a bar's width.
  • .content lays out its direct children as columns, so put one wrapper <div> inside it.
  • A logo in the header must follow the site name's <div> with no space between them, or it drops below the name.
  • A sidebar must follow the page's <div> in .content the same way, </div><div class="sidebar">, or it drops below the page.
  • .btn and other classes that set display override a bare hidden attribute. The kit restores hidden inside its dialogs and bulk bar.

Writing Conventions

  • Title Case for buttons, headings, labels and navigation; sentence case for sentences. "Sign In", not "Log In".
  • Links go somewhere; buttons do something.
  • Button and call-to-action (btn, cta) text starts with a verb that says what happens: "See the Options", "Upload Syllabus", "Explore Categories". Not a topic or a list ("Categories, Grayscale and More", "Options") or a bare "Learn More". Where it leads to a page, follow the verb with that page's heading, so people know they've landed in the right place.
  • A link that needs sign-in gets plain text " [login required]" after it; a link to a file gets its type, " [PDF]". Use one label, never both.
  • Never leave a lone "a" at the end of a line: join it to the next word with &nbsp;.
