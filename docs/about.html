About the Carnegie Mellon Web Kit

The Carnegie Mellon Web Kit fills the gaps in Carnegie Mellon's web template with ready-made components, so Cascade sites and the web apps around them look like one university.

Where It Comes From

Teaching & Learning Innovation built the kit while making the Syllabus Registry, an app and a Cascade site that had to match each other and the rest of cmu.edu. Each component started from a real CMU page that already does it well, and the docs name those pages, so you can see the pattern in use.

The kit builds on CMU's web template, which the university hosts at www.cmu.edu/common/standard-v6. It isn't an official University Communications & Marketing product: for brand questions, see brand.cmu.edu.

Rules

  • The template comes first. See what it already has on CMU Standard, and use its classes as they are: btn, btn small, ghost, cta, table.alternate, .sidebar, .sr-only. The kit never copies the template's rules or values, and adds a class only where the template has nothing.
  • Everything in the kit starts with cmu-: classes, custom properties (--cmu-red), and JavaScript hooks (data-cmu-copy). Variations use a double hyphen (cmu-pill--green). Give your own classes your own prefix, never cmu-.
  • Versions follow semver. Renaming or removing a class is a new major version.

Writing Conventions

  • Title Case for buttons, headings, labels, and navigation; sentence case for sentences. "Sign In", not "Log In".
  • Links go somewhere; buttons do something.
  • Button and call-to-action (btn, cta) text starts with a verb and says what people will do: "See the Options", "Upload Syllabus", "Add Categories, Random Photos, and More". Not a topic, a list of nouns ("Categories, grayscale, and more", "Options"), or a bare "Learn More". Let the action lead; echoing the destination page's heading is nice when it fits, but not required.
  • A button (btn) is the page's main action, and can go wherever that action happens: your app, its sign-in, or a request form in another system. A call to action (cta) is a next step on your own site or app. Any other link to another site is an ordinary link with the template's external class, in sentence case: "Browse the code on GitHub". A link is a cta or external, never both.
  • End a section with its one call to action, after everything that makes the case for it, rather than scattering them through the section.
  • Headings and hero titles don't end in a period.
  • Use the Oxford comma: "red, white, and blue".
  • A link that needs sign-in gets plain text " [login required]" after it; a link to a file gets its type, " [PDF]". Use one label, never both.
  • Never leave a lone "a" at the end of a line: join it to the next word with &nbsp;.

Versions and Checks

Each release is a Git tag, served at a fixed address by jsDelivr, so a page links one exact version and never changes until you move it to a newer one; see Get Started. Every week, and on every change, a check downloads the live template and fails if it has started using a class name the kit uses, so a template update can't collide with the kit unnoticed.
